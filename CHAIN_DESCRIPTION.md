## Описание цепочки для сдачи

## Название
**AI Article Writer — многоэтапная цепочка подготовки и проверки статьи на LangChain**

## Задача
Пользователь вводит тему и требования к статье → система анализирует задание → разрабатывает план → пишет статью → проводит редакторскую проверку.

### 0. Приём задания (интерактивный ввод)
Пользователь вводит тему, аудиторию, цель, стиль, объём, обязательные темы и запреты. Всё можно задать аргументами командной строки (`--topic`, `--audience`, `--goal`, `--style`, `--length`, `--must`, `--avoid`, `--yes`), либо ввести в консоли с значениями по умолчанию. Собранный `TaskBrief` передаётся во все последующие этапы.

### 1. Анализ задания
LLM определяет цель статьи, аудиторию, стиль, ключевые вопросы, требования к объёму и критерии качества. Строго учитывает ограничения и обязательные темы из задания.

### 2. Подбор/проектирование
Для статьи формируется план: заголовок, разделы, тезисы и логика раскрытия темы. Разделы должны покрывать обязательные темы из задания.

### 3. Реализация
LLM получает тему, анализ, план и задание — генерирует полный текст статьи с учётом аудитории, стиля, объёма и ограничений.

### 4. Проверка / ревью
Отдельный этап выступает независимым редактором: сначала проверяет соответствие заданию заказчика (цель, аудитория, объём, стиль, раскрытие обязательных тем, отсутствие запрещённого), затем оценивает статью по шкале 0–10, находит недостатки, фактические риски и предлагает улучшения.

## Итоговая схема

```text
┌─────────────────────┐
│ 0. Приём задания    │ (интерактивный ввод)
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│ 1. Анализ задания   │
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│ 2. План статьи      │
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│ 3. Написание        │
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│ 4. Редакторское     │
│    ревью             │
└──────────┬──────────┘
           ↓
       Готовая статья
```

## Почему LangChain
LangChain позволяет представить каждый этап как отдельный Runnable и передавать результат одного этапа следующему. Структурированные результаты этапов 0, 1, 2 и 4 описываются через Pydantic. Задание (этап 0) проходит через всю цепочку: от анализа до ревью.

## Возможное расширение
Можно добавить Web Search или RAG между планированием и написанием:

`Приём задания → Анализ → План → Поиск источников → Написание → Проверка фактов → Ревью`.
